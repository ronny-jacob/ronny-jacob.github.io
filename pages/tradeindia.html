The problem

The system used the full product name as the search keyword, across tens of thousands of inquiries a day. I traced the journey from inquiry to seller notification and found the keyword step was the bottleneck. The first release also had to cost nothing to run and work with a 2-billion-parameter model.

What I did

  • Ruled out SpaCy: 43% on the 10,000-product test set. Measured
  • Compared six models: GPT-4o, Claude 3.5 Sonnet, Mistral Large, DeepSeek V3, Gemini 2.5 Flash Lite and Gemma 2.
  • Tested 14 prompt variants with fixed settings. Clear steps beat example-heavy prompts, and extra rules caused errors, so I moved edge cases into code. Best prompt: 86%. Measured
  • Added a validation pipeline: Gemma 2 went from 76% (original prompt) to 88%. Measured
  • Automated testing: a cycle went from 1–2 hours on 20–50 keywords to 5–10 minutes on 500–1,000+. Measured

Limits and next steps

  • These are offline test results. The original prompt scored higher in my controlled tests than in the team’s earlier production testing, so I expect production to land lower.
  • A 2B model has a ceiling. Retries and fallbacks stop bad output but cannot fix a plausible wrong keyword.
  • Shorter keywords match more sellers and can match the wrong ones. I handled this with the pipeline, not a measured precision metric.
  • Next: run Gemini 2.5 Flash Lite on the same test set in production, find the test-to-live gap, and measure sellers reached per inquiry.
